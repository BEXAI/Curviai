# Full codebase audit against CURVI_BUILD_PLAN.md

Date: 2026-09-27. Method: 11 audit agents, one per plan dimension, each followed by an adversarial verifier that attempted to overturn every non met claim by searching the whole repo and the phase docs. 257 concrete plan requirements checked. Every finding below survived verification with file and line evidence.

Roughly a third of the gaps are documented deferrals in docs/verification.md or docs/phases (accounts, keys, certificates that do not exist yet). The rest are real build gaps. The overall shape: the deterministic pipeline, DB layer with RLS, AI reliability primitives, seeds, specs and marketing surface are solidly built and tested, but the connective tissue between them is missing. Modules exist and pass their unit tests while nothing invokes them on the production path.

## The three P0 findings

All three were fixed the same day; see the remediation section in docs/verification.md for what landed. The list below records what the audit found before the fix.

1. No bridge from the web app to the worker. POST /api/jobs inserts a generation_jobs row, reserves credits, and stops. apps/web has no Trigger.dev dependency and never enqueues generate-pack, so in db mode every job stays queued forever and its credit reservation is held forever. The charge_credits and release_credits SQL functions are dead code on the live path.
2. Credits never settle in db mode. The in memory runner has a complete, tested reserve, charge per passing asset, release on failure ledger flow, but no DB backed JobStore exists, so nothing writes job_steps, assets, packs, charges or releases to Postgres. Also the integer delta column cannot represent the plan's 0.5 credit deterministic assets.
3. No way to see or download any produced file. The packager writes correctly named per channel zips to a worker local temp dir. There is no R2 upload of outputs, no download route, no channel tabs, no before and after reveal in the app. A paying user could never receive a pack.
