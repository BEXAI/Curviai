## Contracts inspected

- `show_pack` uses `packs:read` and the same `getPack`/`packView` path as `get_pack`. The principal supplies the workspace; the strict argument schema permits only an existing pack ID. The route authenticates the connection and rereads membership before invoking services. Client seats may read workspace assets under the existing product role contract.
- Viewer refresh uses only `get_pack`. Further tracing found existing reconciliation could also charge previously delivered work; P22-R5 supersedes the initial narrower interpretation that it only released holds. The internal read option now suppresses that business mutation for MCP get/show/estimate, with real database fixture assertions.
- The other read-only tools were traced independently: `list_channels` projects the registry/entitlements and reads its stored feature switch (`actions.ts:902`, `services/db.ts:1230`, `platform-settings.ts:12`); `get_profile` projects the authenticated identity (`mcp-auth/profile.ts:36`); `check_main_image` performs bounded photo reads and deterministic in-memory pixel analysis (`actions.ts:836`, `api-v1/photos.ts:201`). No job, ledger, stored-photo or completion-event write was found in those actions. Shared authorization/rate-limit bookkeeping is separate from business mutations.
- Delivered files originate from the existing workspace-scoped service, which lists picked variants and stored pack files. This viewer adds no raw-source lookup and no alternate file-signing path. Link delivery keeps its separate subject/workspace/file checks.
- Terminal host results are treated as potentially restored data: candidate code hides their signed URLs and requests an authenticated read before starting link age. Saved widget state contains a pack handle and presentation choice, not URLs or credit claims. Failed/canceled packs can display only the valid delivered files supplied by the server.
- Candidate UI keeps text-only rendering, same-origin preview/file paths, parent-source bridge validation and a fixed versioned resource with narrow resource CSP. Fidelity copy distinguishes recorded measurements, missing measurements and a true stored byte-for-byte flag.
- Submission mode is a local package gate. A successful build explicitly leaves verified publisher identity, current portal scan, actual ChatGPT behavior, reviewer access, attestations, submission, approval and publication unproved.
