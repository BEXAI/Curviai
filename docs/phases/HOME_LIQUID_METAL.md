# Home page overhaul: the liquid metal hero

Date: 2026-09-29. Branches: home/liquid-metal (the build), home/liquid-metal-final (the review fixes). Asked for by the founder: a large UI overhaul of the home page built around a pasted 21st.dev component, LiquidMetalHero (a full bleed animated liquid metal WebGL shader from @paper-design/shaders-react behind a centered hero with a badge, a very large headline, a subtitle, two calls to action and a frosted feature card, with a staggered entrance).

## Decisions

| Decision | Why |
| --- | --- |
| The hero lives in apps/web/src/components/ui/liquid-metal-hero.tsx (the new home for imported UI components). It is not a client component. | The H1 is the LCP element and carries SEO. It must be server HTML, visible without JavaScript, never faded in from opacity 0. Chromium leaves opacity 0 elements out of LCP until they show. |
| Button, Badge and Card come from @curvi/ui. No shadcn copies, no @radix-ui/react-slot, no class-variance-authority. | One component system. The burgundy secondary Button stays the call to action. Links use buttonVariants on next/link, as elsewhere. |
| shadcn tokens mapped to ours: foreground to white, background to night, foreground/90 to ink-100, glass to bg-night/80 with a white/15 hairline. The missing Badge variant "secondary" became the default Badge with overrides. | No second token system. text-foreground generates nothing in our Tailwind v4 theme. |
| Wine tokens in the @theme block: wine-300 #d0587a, wine-500 #b03a5b, wine-600 #8f2749, wine-700 #7a1f3d, wine-900 #4a1226, wine-950 #3b1a26. The secondary Button, the headline line, the pricing ring, the glass tile glow, the pack drawings and the CSS metal use them. | Brand color changes are token changes. The shader tint is the one literal (the library needs a color string); it matches wine-500. |
| Calls to action are links only: "Start free" to /signup (burgundy), "Test your main image free" to /tools/main-image-checker (the new glass Button variant). Hrefs are required; the original click handler props and the button branch are gone. The header's signed out call to action says "Start free" too. | A server component cannot pass click handlers, and a call to action without a target would be a control that does nothing. One label for one destination. |
| The secondary Button's focus ring is wine-300: 5.1:1 on night and 3.9:1 on white. | WCAG 1.4.11. The old #8f2749 ring was 2.4:1 on night, on every page of this dark site. |
| A glass Button variant in @curvi/ui (white hairline, white/5 fill, white focus ring), used by the hero and the pricing section. No backdrop blur anywhere on the home page except the header. | One definition instead of two copies. A blur over the shader is refiltered on every frame it draws, and on near uniform night it shows nothing. |
| No framer-motion. The stagger is CSS: the headline and subtitle use a rise-in keyframe that moves but never fades; the badge, calls to action, note and card use fade-in-up at 0, 240, 300, 360 ms, and the card items at 440, 520 and 600 ms. Every entrance class and delay is motion-safe, so under reduced motion nothing animates or waits at opacity 0. Hover lifts by 2 px on motion-safe devices. | Same look for 0 KB of JavaScript, running before hydration. framer-motion writes opacity 0 into the SSR HTML and cannot tree shake below about 34 KB. The global reduced motion rule shortens durations but not delays, so gating the classes is what makes the entrance instant. |
| @paper-design/shaders-react pinned to exactly 0.0.81, Apache 2.0. | 0.0.47 to 0.0.76 were PolyForm Shield (noncompete); 0.0.77 and later are Apache 2.0. The maintainers ship breaking changes under 0.0.x and ask users to pin. NOTICE kept in THIRD_PARTY_NOTICES.md. |
| The shader is a client island in two files: liquid-metal-backdrop.tsx (gate, fallback, crossfade, error boundary, motion toggle) and liquid-metal-canvas.tsx (the shader), loaded with next/dynamic and ssr false at idle time. | The library stays out of the first load bundle (its lazy chunk is about 12 KB gzip) and never runs on the server. |
| The shader runs only on a desktop sized screen with a fine hovering pointer ((min-width: 48rem) and (min-height: 30rem) and (hover: hover) and (pointer: fine)), without reduced motion, without Save-Data, with 4 GB or more of memory and 4 or more cores where reported, and with WebGL2. The cheap checks run after hydration; the WebGL2 probe (a throwaway context) waits for the idle callback. | Phones in either orientation and tablets keep the static metal, where the shader would only cost battery. A first WebGL context can take tens of milliseconds, which must not land where first input happens. |
| It unmounts live when reduced motion turns on, and falls back for good after a lost WebGL context, a library error, or a shader chunk that fails to load. A small error boundary around the lazy canvas catches the last two. | The library throws inside an async effect without WebGL2, which no boundary catches, hence the probe. A rejected lazy import throws at render time and, unbounded, would replace the whole page with the root error page. |
| The crossfade starts only after the shader has drawn its first frame (its mount exists and its canvas has a size). | The library builds its program asynchronously and draws on its first resize; fading in before that shows an empty canvas. |
| A "Pause background motion" / "Play background motion" button sits at the hero's bottom right while the shader runs. It sets the shader's speed to 0, which stops its animation loop, and the choice is remembered in localStorage (read and written in try/catch). It comes after the hero content in the tab order. | WCAG 2.2.2: the metal starts on its own, runs longer than five seconds and sits beside the text. A reduced motion preference is not a pause mechanism. |
| The shader is scoped to the hero (absolute, oversized past the hero's edges and clipped), never position fixed. minPixelRatio 1, maxPixelCount 1280 by 720. | The library pauses its loop when its element leaves the viewport or the tab is hidden; a fixed mount always intersects and never pauses. The cap is several times fewer pixels than the library default of 2x and 8.3 megapixels. |
| The pasted `{...liquidMetalPresets[2]}` was a bug: presets are `{ name, params }`, so it rendered the default diamond and leaked `name` and `params` onto the div. The canvas writes its values out, starting from the Backdrop preset. | A version bump must not change the look silently. |
| Brand tuning: colorBack night #07080d, colorTint #b03a5b (wine-500), shiftRed 0.15, shiftBlue 0, speed 0.35. Compared on 2026-09-29 on fixed frames (20 s and 60 s of animation time, speed 0, 1440 by 900) against #d0587a with shiftRed 0.3 (the first build), #d0587a with 0.2 and #b03a5b with 0.2. | The first build's fringes read saturated red and cyan. The deeper tint with half the red shift keeps the chrome wine, next to the #7a1f3d call to action and the #b03a5b headline, with the least fringe. |
| The static CSS metal (.hero-metal-fallback) is chrome tubes drawn with three elliptical ring gradients (dark, silver and wine bands) over night, with a wine glow from the top right and a teal glow from the lower left. No filter. It always renders first and stays for reduced motion, no WebGL2, phones and tablets. The closing section reuses it. | It reads like the shader's swooshes instead of a vignette, costs no blur pass, and shows no layout shift or blank hero while the chunk loads. |

## Contrast

Measured on the rendered page on 2026-09-29, not estimated: the hero's glyphs were hidden (the headline halo stays, it is part of the background), the page captured, and every text line compared with the brightest pixel inside its line box. For the shader, the loop was stopped and the check repeated on 6 to 10 frames between 0 and 81 seconds of animation time.

| Viewport | Wine headline line (needs 3:1, large) | Other hero text (needs 4.5:1), lowest |
| --- | --- | --- |
| 320 by 568 phone, static metal | 3.30 | 6.81 (the note) |
| 360 by 800 phone, static metal | 3.31 | 6.89 (the note) |
| 430 by 932 phone, static metal | 3.30 | 8.17 (the note) |
| 844 by 390 phone in landscape, static metal | 3.26 | 13.29 |
| 1280 by 800 desktop, reduced motion | 3.23 | 13.24 |
| 1024 by 768 desktop, shader | 3.23 | 13.12 |
| 1440 by 900 desktop, shader | 3.22 | 9.30 (the badge) |

How it holds: the scrim (.hero-metal-scrim) paints, top to bottom, a fade to night at the hero's bottom edge, a pool of night, then the wine and teal glows, so the glows light the metal around the text and never tint it. On 40rem and wider the pool is an ellipse (56rem by 30rem at 50 percent 44 percent) that is 96 percent night out to 62 percent of its radius, then 50 and 25 percent at the flanks. On phones the hero is one text column whose text block sits between about 9 and 64 percent of the hero's height at every phone size measured (320 to 430 wide), with the headline between 13 and 30 percent; the pool is banded down the page: 95 percent night behind the headline, 78 percent behind the subtitle, calls to action and note, and thin above the badge and around the feature card, so the chrome shows there. The wine line also carries a four layer night text shadow halo. The note moved from ink-300 to ink-200. The feature card is bg-night/80 and the badge bg-night/70, which keep their text above 9:1 whatever the metal does.

e2e/home-hero.spec.ts repeats this measurement for the wine line and the note at 1280 wide under reduced motion, at 320 and 390 wide on phones (also the subtitle and the glass call to action), and on four shader frames where this browser runs the shader, so a scrim, copy or font change that drops a line under its minimum fails CI.

`.theme-base` restores Tailwind's own red, amber and emerald tints. Inside the home page's theme-base scope they were still the dark theme's, so the white example compliance report showed light green text on white. Small text on night uses ink-400 or lighter (ink-500 is 4.3:1 and fails).

Founder decision still open: keep "Ready everywhere." in wine-500 #b03a5b (the default here, 3.2 to 3.3:1 at worst) or use the lighter wine-300 #d0587a for the hero line only (5.1:1 on night, and more metal could show behind the words). It is one class in page.tsx (headlineWine).

## Page order

1. Hero (LiquidMetalHero): badge homeHero.eyebrow, H1 "Shot once. Ready everywhere.", subtitle homeHero.lead, the two calls to action, the free credits note, three live promises (fidelity, compliance report, channel count), and the motion toggle while the shader runs.
2. Before and after: the unchanged BeforeAfterSlider with its Illustration label and caption, the fidelity lock tile, homeHero.proof and a gallery link. The UploadBox is gone: it repeated the hero's Start free, No card needed and free tool link word for word a few hundred pixels lower, and on phones its drop area did nothing.
3. How it works: the three homeSteps with outline numerals.
4. What a pack contains: one tile per line of the typical pack estimate (typicalPackLines, the new pack form's own estimate). Tiles are titled by name with the count as a chip ("Background sweeps", "2 files"); a line that is not delivered gets the dashed coming soon treatment and the shared Coming soon label instead of its credits. Then the brand kit tile, the credits summary, and the two coming soon features under an "On the way" label.
5. Proof on every file: the compliance report tile and the example report.
6. Channels: the channel ready files tile with a short body (the tiles below name every channel), and one link per live channel to its requirements page; Amazon spans both columns on phones, so nine tiles fill five rows.
7. Pricing: home-pack-size, the Stripe conditional note, a Free tile with the burgundy Start free and the four paid tiers from the seed.
8. FAQ: homeFaqs, which still feed the FAQPage JSON-LD in order, beside a sticky aside.
9. Guides and free tools: the four pillar pages in the Guides nav and the three free tools.
10. Closing: static metal at the edges with a pool of night behind the text, the email form and a free tool link. The Wordmark is gone from here (the sticky header and the footer already show it).

Eyebrows appear only where they add something to the H2 (Before and after, What a pack contains, Compliance report, Learn the rules). Every homeFeatures entry renders once through FeatureTile, so each feature-{key} test id is unique and exactly the two coming soon features carry the Coming soon label. Metadata, JSON-LD and the footer links are unchanged; the hero lead now opens "Turn one photo into AI product images for Amazon, Shopify, ..." so it keeps the target phrase without repeating the badge's opening words.

Every grid that phones see as one column says grid-cols-1 (minmax(0, 1fr)) with min-w-0 columns, so a wide child such as the example report scrolls inside its own box instead of stretching the track past the screen. The page wrapper uses overflow-x-clip, not overflow-hidden: hidden made it a scroll container, which froze the .reveal view() timelines and the sticky FAQ aside.

Below the fold, tiles use a CSS scroll driven reveal (.reveal) inside `prefers-reduced-motion: no-preference` and `@supports (animation-timeline: view())`. It starts at opacity 0.001, never 0, and finishes once 30 percent of an element is in view. Tall blocks that hold body text (the slider column, the example report) do not use it.

## Tests

- apps/web/src/components/ui/liquid-metal-hero.test.ts: headline, subtitle and link targets in the server HTML; no inline style or opacity on the H1 and subtitle; both calls to action are links and no button renders on the server; every entrance class is motion-safe; no backdrop blur in the hero; the static metal renders on the server with no canvas and nothing fixed; copy rules; one H1 on the home page; the shader gate truth table, and no WebGL probe for reduced motion or phones.
- marketing-render.test.ts: pack tiles title by name with a count chip, a coming soon line gets the label and no credits, and every line of the typical pack renders as live or coming soon; the header offers Start free.
- claims.test.ts: every home copy export is in liveCopy (coming soon and copy rule checks), and the home files are in OWNED_SOURCES (no literal credits, prices, percents or 3 digit px).
- e2e/home-hero.spec.ts: without JavaScript the hero shows, and with every time based animation frozen at its first frame the H1, the subtitle and all their ancestors are at opacity 1; the server H1 has no opacity; reduced motion keeps the static metal with nothing animating or hidden; a phone, a phone in landscape and a tablet get no shader; measured contrast on phones, under reduced motion and on shader frames; no section wider than a 360 px phone; no page errors, nothing fixed and no backdrop filter in the hero. Where this browser would run the shader: it turns on, pauses offscreen and resumes, stops live when reduced motion turns on, can be paused and played with the choice remembered, falls back without WebGL2 (stubbed), and keeps the page when its chunk fails to load (aborted). Keyboard: the hero Start free ring is at least 3:1 on night and the glass one is white. Below the hero: the FAQ aside sticks at 96 px and a pricing tile reveals as it scrolls in; every channel link returns 200.
- e2e/claims.spec.ts: the hero note states the free grant, the page has no file input, and every pack tile is live or labeled coming soon.
